# 架构与实时协议

## 组件边界

项目由两个运行时代码文件组成：

- `server.js`：Node.js 18+ HTTP 服务和手写 WebSocket 帧处理器；负责房间、玩家名单、关卡种子、排名和消息转发。
- `sheep-river-3d_4.html`：静态客户端；负责页面、输入、音效、Three.js 场景、碰撞、计分和远端玩家插值渲染。

HTTP 仅提供 `/` 和 `/sheep-river-3d_4.html`；WebSocket 仅在 `/ws` 升级。客户端会根据页面协议自动选择 `ws:` 或 `wss:`。

## 房间生命周期

```text
创建/加入 → lobby → 房主 start → playing → 全员完成当前关卡
                                              ├─ 下一关：playing
                                              └─ 最后一关：complete
```

房间数据保存在进程内 `Map` 中。玩家断开后会被移除；房主断开时，当前房间中的下一位玩家成为房主；空房间会删除。服务重启会丢失所有房间和进度。

## 协议

所有消息均为 JSON 文本帧。客户端先发送 `create` 或 `join`，之后才能发送其他业务消息。

| 方向 | 类型 | 主要字段 | 作用 |
| --- | --- | --- | --- |
| C → S | `create` | `name` | 创建房间并加入 |
| C → S | `join` | `name`, `roomCode` | 加入候客中的房间 |
| S → C | `joined` | `id`, `code`, `hostId`, `levelIdx`, `levelSeed` | 返回本客户端身份与房间初始信息 |
| S → C | `room` | `phase`, `players`, `levelIdx`, `levelSeed` | 广播完整房间快照 |
| C → S | `start` | — | 仅房主可启动第一关 |
| C → S | `state` | `state` | 上报本地位置、方向、跳跃和可见性 |
| S → C | `playerState` | `id`, `state` | 转发某位玩家的状态 |
| C → S | `complete` | `levelIdx` | 报告完成当前关卡 |
| S → C | `error` | `message` | 报告可展示的错误 |

`state` 坐标被服务端限制在 `-100` 到 `100`，方向限制为四个合法值，且 `levelIdx` 必须与房间当前关卡一致。客户端最多每 75 ms 发送一次状态；远端小羊在客户端进行平滑插值。

## 一致性与权威性

服务端生成 `levelSeed`，客户端用相同种子生成木筏和场景，因此同一房间看到一致的关卡布局。服务端只协调房间状态，不验证碰撞、得分或真正抵达终点；客户端上报的完成消息会被接受。这是合作游戏的轻量实现，不是防作弊实现。

## 当前限制

- 单进程、内存态，不能跨实例共享房间；不支持水平扩容。
- 无登录、身份校验、断线重连、持久化、限流或健康检查端点。
- Three.js 在浏览器运行时通过公共 CDN 加载；网络或 CSP 限制可能阻断游戏画面。
